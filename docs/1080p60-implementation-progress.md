## 2026-10-30 更新：公司内网双端有线

Windows 10.11.42.3 与 Linux 10.11.42.4 均协商 1 Gb/s，全双工；媒体地址已分别绑定并通过实际 ICE 地址核对。负载期间 35 次 ICMP 往返 0–1 ms、无丢包，不能据此推断交换机全部端口或端到端吞吐。

GCC / ICE-TCP 真实 GNOME 桌面三次启停通过；随后两次 60 秒 Edge 动态压力平均显示 59.91 / 59.94 fps，第二次 1080p 显示间隔 p99 26.2 ms、最大 87.64 ms。单秒统计各有 1 次低于 58 fps。压力脚本第二次启动/关闭 7 次、最小化/还原 19 次、缩放 57 次。

相同条件下 GCC / ICE-UDP 完整用例通过，60 秒 Edge 压力平均显示 59.85 fps、显示间隔 p99 25.1 ms、最大 92.70 ms；所有 1 秒样本均不低于 58 fps。连续画质采样阶段约 59.90 fps、最大间隔 192.63 ms。拖拽输入至解码帧的 p95 为 82.35 ms（75 个样本）；TCP 同项为 80.24 ms（67 个样本）。这些不等同于输入至物理屏幕显示的延迟。

第一轮压力后的画质断言失败：检查使用了窗口隐藏前坐标。GNOME 恢复后测试窗口 Y 从 380 变为 345；测试现读取恢复后的坐标并保存前后值，不改变画质标准。第二轮单像素颜色平均误差 0.585、最大 5，完整远控及画质用例通过。连续画质阶段涉及截图和像素检查，显示约 54.37 fps，最大间隔 185.321 ms，超过 200 ms 的间隔 0 次。生成证据在 `build/analysis/lan-wired-20261030/`。

Windows Release 重新构建时 signaling / media 通过；core 的默认临时目录创建失败，使用仅针对测试进程的项目生成目录后 core 29/29 通过。构建脚本因首次 core 失败而未执行部署。Linux UI 测试目标重新构建通过。本轮尚不能宣称 30 分钟稳定 60 fps；HEVC 产品接入和长稳验收仍未完成。
