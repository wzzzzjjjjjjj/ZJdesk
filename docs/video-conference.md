# 两人视频会议

在“视频会议”页输入会议房间码并加入，另一端需进入相同类型的房间。会议与协作空间的同码房间互不相通，且一个客户端一次只能加入一个房间。请同时更新信令服务和客户端；旧服务无法确认会议类型时客户端会拒绝入会。页面可启动本地预览和屏幕共享，会议房间不提供远程控制。

双方使用包含会议功能的新客户端和信令服务，启用 GStreamer 1.26.11，加入同一个两人房间。
在左侧选择“视频会议”，选择摄像头、麦克风与扬声器；“默认设备”表示第一个支持的设备。
一方点击“发起视频会议”，另一方的会议页显示来电，点击“接听”后双方才开始采集和传输。
点击“拒绝”或“挂断”结束该次通话；房间与独立屏幕共享继续保留。

通话中可以切换“麦克风静音”“扬声器静音”和“隐藏画面”。隐藏画面会发送黑帧，
摄像头仍在采集；麦克风静音会发送静音数据，麦克风仍在采集。挂断才释放设备。
设备在呼叫前选择，来电时可以调整后再接听；切换设备需挂断重拨。
开始通话会自动停止本地预览和测试音，等待其设备释放后再启动会议。

会议采用 VP8 640×480 / 30 fps、800 kbit/s 目标视频码率和 Opus 单声道 48 kHz / 32 kbit/s。
实际帧率取决于采集设备和网络。使用耳机避免扬声器回声；当前没有声学回声消除。
不支持音频单独入会或自动降为纯语音；缺少摄像头、麦克风或音频输出会结束该次通话并显示错误。
拒接、挂断、设备失败、对方离开、信令断开以及 45 秒呼叫或媒体连接超时均会清理该次会议。

媒体直接使用 ICE 主机候选地址，适用于双方可达的局域网或已有互通网络。
当前没有配置 STUN / TURN 中继，单纯连接同一个信令服务器不能保证跨 NAT 通话。
服务仅转发协商消息，摄像头与语音通过独立加密 WebRTC 会话传输。

## 回归与实机验收

`build.ps1` 的 media 回归使用两个真实 WebRTC 管线、合成摄像头 / 麦克风和无声输出。
覆盖双方解码画面与非零音频、麦克风 / 扬声器静音后恢复、黑帧替换、连续两次通话、
预览与测试音释放、通话期间共享屏幕、拒接、交叉呼叫、离开清理和缺失设备错误。
这些结果不代表物理设备、真实双机网络或声学效果已验收。

`zjdesk-ui-tests conferenceControlsAndFrames` 是需要实际桌面的会议 GUI 回归，
检查来电页面、按钮状态、设备锁定、原生 OpenGL 画面及挂断清屏。不可用 offscreen 结果替代。

实机验收时分别在 Windows 与 Ubuntu 22.04 选择真实设备，佩戴耳机，确认双方画面与声音；
逐一验证三项静音 / 隐藏控制、挂断重拨、来电拒绝、退出房间、重新入会和同时共享屏幕。
持续通话期间检查设备占用、音画流畅性及断网后的错误提示。真实设备、原生 GUI 和双机验收仍待执行。
