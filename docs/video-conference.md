# 局域网视频会议（最多四人）

在“视频会议”页输入相同会议房间码，最多四位成员自动建立连接。会议与协作空间按类型隔离，即使房间码相同也不会互通；一个客户端一次只能加入一个房间。协作远控仍限两人，会议可由共享者授权一位成员控制当前共享桌面。客户端与信令服务须一起更新，旧服务不支持四人定向协商。

进入会议页会自动刷新摄像头列表；没有设备时显示灰色“无可用设备”。右上角可以编辑昵称，侧栏“设置”中选择摄像头、麦克风、扬声器、测试声音或刷新设备。“默认设备”选择第一个支持的设备。界面不提供独立预览或合成视频源，通话时显示本机与远端画面。

设备下方的三个“入会后默认开启”开关初始均开启，保存在本机。下次启动会议连接时应用，通话中修改不改变当前开关；临时静音也不覆盖保存的默认值。开始采集前先停止测试音并等待设备释放。只有一人在房间时不占用通话设备，等待其他成员。

界面为本机和最多三位远端显示视频或昵称头像。人数来自实际入房成员，即使某位成员音视频失败也会保留其身份。连接状态显示已连接的远端数 / 远端成员数；一人失败或离会只移除对应媒体链路，其余成员继续通话。离会后重新加入自动连接；失败不会循环重试，排除故障后请离会重入。

通话中可以切换麦克风、扬声器和摄像头。隐藏摄像头后各端显示该成员的昵称头像，恢复后重新显示视频；隐藏状态按成员和当前会话同步。隐藏时仍采集并发送黑帧，静音仍采集并发送静音数据；离会才释放设备。切换设备需先离会，选择设备后重入。

屏幕共享支持一人向其余最多三位成员发送，使用独立 VP9 桌面链路。共享权由信令服务统一确认；第三、第四位成员加入后自动接收，一位观看者离开不停止其他人的共享。共享者离开、停止共享或最后一位观看者离开会结束当前共享并清空标注。

共享画面上方提供“浏览 / 画笔 / 圆圈 / 箭头”。选择绘制工具后，按住左键在画面中拖动，其他成员同步看到对应颜色的笔画，画面右上角统一显示颜色与昵称图例，同一作者只列一次，笔画旁不再重复署名；标注坐标随共享画面缩放和全屏保持对齐。每人可“清除我的”，共享者可“清除全部”。共享者的真实桌面另有鼠标穿透的透明标注层，便于操作其他软件时看到指示；直接绘制仍在会议共享预览中完成，不需要取得远控权限。晚入会回放当前画布，最多 128 条标注、每条 256 点，长画笔自动分段，达到容量时需先清除。

共享期间，观看者点击“申请控制”，共享者选择该成员后点击“交给所选成员”批准，也可直接指定一位成员。一次只有一位成员具有控制权；共享者可随时“收回控制”或选择另一成员，切换会使旧授权立即失效。已有控制者或待处理申请时，其他申请自动结束，由共享者决定下一位成员。申请 30 秒未获批准会取消。

取得控制权后，工具切到“远控”，点击共享画面即可操作键鼠。切到“浏览 / 画笔 / 圆圈 / 箭头”会释放已按键鼠并暂停发送输入，控制权保留，选择“远控”可继续操作；“释放控制”结束授权。标注画布在控制权切换时保留。共享结束、共享者或控制者离会、控制通道关闭时撤销授权并释放键鼠。更换共享者需要重新授权。会议控制只作用于当前共享主屏幕，Windows 使用 SendInput，Linux X11 使用 XTest。

Windows 在本机会议桌面共享期间，将程序主窗口和桌面标注层排除出采集，避免放大预览时不断录入自身；其他成员看到窗口后方的桌面内容，标注仍单独同步。停止共享或离会后恢复主窗口正常采集。Linux X11 的标注会随桌面进入视频，观看端避免重复绘制。Wayland 暂不支持桌面共享。实际异网验证使用现有 Tailscale 互通网络，不代表已支持任意公网穿透，详见 [多人标注验证](validation-meeting-annotations-20261108.md)。

共享屏幕、本机和每位远端成员的画面右上角均有“放大”按钮，点击后单独全屏显示；点击同一位置的“缩小”或按 Esc 恢复原窗口和布局。放大期间继续接收和绘制画面，不重新建立媒体连接。正在查看的成员离开、画面被清空或成员位置发生更换时自动恢复布局，避免把另一位成员误当成原画面。隐藏摄像头时仍显示昵称头像。

## 媒体与网络

每个客户端只打开一次摄像头、麦克风和扬声器。四人采用全互联，每台最多三路独立 WebRTC 编码 / 解码，远端音频通过 `audiomixer` 汇总到一个输出，支持多位成员同时发送声音。需要 GStreamer 1.26.11 的 `appsrc`、`audiomixer` 等组件；启动诊断检查缺失插件，不能混用系统旧版插件替代。

摄像头采用最高分辨率及该分辨率下最高帧率采集。输出使用 VP8，按各路实际编码速度和共享本机帧交付速度自动调整：先保持分辨率降低帧率至 15 fps，持续吃紧才降低尺寸；稳定后优先恢复分辨率再恢复帧率。原生输入保持最高模式，输出降档不能保证解决驱动 / 解码瓶颈。

每路编码最多两条线程。1280×720 / 30 fps 档位目标约 2 Mbit/s，Opus 为单声道 48 kHz / 32 kbit/s。四人时每台三路视频目标合计约 6 Mbit/s，另加音频与协议开销；这不是最低线路配置或实际码率保证，也不保证每台电脑达到目标帧率。当前按本机处理能力调整，没有会议网络拥塞自适应。

每对成员有独立的连接状态和 45 秒连接期限，超时移除该路，保留已运行的其他连接。共享采集设备失败会结束本机会议；退出房间、信令断开或最后一位远端离开会清理采集和播放设备。

媒体使用 ICE 主机候选地址，需要所有成员之间的动态媒体端口互通；只连接同一信令服务器不能保证媒体连通。当前无 STUN / TURN，适用于可信局域网或已有互通 VPN。信令只转发协商消息，音视频由独立加密 WebRTC 会话承载。建议使用耳机，尚无声学回声消除，也不支持纯语音入会。每位成员均需可用的摄像头、麦克风及输出设备。

## 回归与实机验收

`build.ps1` 的 signaling 回归覆盖四人入房、拒绝第五人、定向转发和成员离开 / 重入；协作房间仍拒绝第三人。media 使用真实 WebRTC 管线及合成设备，覆盖两人原有呼叫接口、自动连接、入会默认开关、静音 / 隐藏 / 恢复、并行双人共享和设备清理。

`conferenceFourMembersLeaveAndRejoin` 逐步验证二至四人，每位成员接收其他三人的视频 / 音频；三路音频分别开关以确认每个混音输入确实到达输出，同时发送时输出非零；一人离开 / 重入时其余链路继续传帧。`meetingAdaptsToSlowFrameConsumer` 阻塞共享画面消费者，检查媒体工作线程仍能下调输出并保留原尺寸。

`zjdesk-ui-tests meetingFourVideoTiles` 需要真实桌面，检查 1040×720 布局、四个原生 OpenGL 画面、三路远端帧、成员离开和独立超时不终止剩余连接。`conferenceControlsAndFrames` 检查设备锁定、隐藏 / 恢复及离会清屏；`workspaceFitsSmallWindowAndLongNames` 检查小窗口和长昵称；`meetingJoinDefaultsPersist` 检查设置保存；`localPreviewIsNotAvailable` 和 `meetingEntryRefreshesCameraAndHintsMissingDevice` 保留原设备入口回归。不可用 Qt offscreen 结果替代。

2026-11-04：完成 Windows ↔ Ubuntu 两机真实摄像头 70 秒和两机四进程 90 秒验证，每机一个真实摄像头成员、一个合成成员，所有进程报告连接成功及设备释放。相互收到 1280×720；Ubuntu 图像仍偏暗，用户暂无法确认镜头挡板 / 光照，实际画面内容尚未验收。音频使用合成源和无声输出，未打开真实麦克风或扬声器。详细结果见 [会议验证记录](validation-meeting-20261104.md)。这些结果不能替代四台实体机、真实音频听感或长期稳定性验收。

后台摄像头探针为 `zjdesk-meeting-probe`（启用 GStreamer 且 `BUILD_TESTING` 的构建生成）：

```powershell
.\build\windows-release\bin\zjdesk-meeting-probe.exe --server ws://信令地址:8765 --room camera-check --name Windows --members 2 --seconds 70 --exercise --snapshots build/camera-check
```

默认选择真实摄像头，麦克风和输出始终为合成 / 无声且静音；`--camera test` 使用合成摄像头。`--exercise` 在测量的 25% / 35% 时隐藏 / 恢复、50% / 60% 时离会 / 重入。日志记录各成员帧数、尺寸、最大交付间隔以及结果与退出释放；结果不根据房间连接直接判定，要求所有预期远端 running、有画面且最近三秒仍收到帧。测量结束保留成员身份五秒后离开，两端请在五秒内启动。探针不安装为正式客户端，运行时需可用的 Qt / GStreamer 环境。

后续实机验收：确认两端明亮、可辨认的摄像头内容；接真实麦克风与耳机检查静音、恢复及同时说话；用三至四台独立电脑完成入退会、异常退出及多人共享，并检查至少 30 分钟的帧间隔、CPU / 内存 / 设备占用。
