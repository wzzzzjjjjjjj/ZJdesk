# 在协作空间验证对端 IP

直接运行程序即可显示主界面，不弹出单独的 IP 输入窗口。协作空间的启动卡片只保留「对端 IP」一个输入框和「连接服务」一个按钮：服务地址由验证自动设置，昵称只在页头填写。空输入框显示红色边框，远控和会议在验证通过前不可用。构建 / 部署不要求输入 IP，用户实际打开程序时再验证。

## 1. 查询地址

- Windows：按 Win + R，输入 `cmd` 回车，执行 `ipconfig`。取当前以太网或无线网卡的 IPv4 地址。
- Linux：在终端执行 `ip -4 addr show up`。取正在使用的网卡 `inet` 后、`/` 前的地址，例如 `inet 192.168.1.20/24` 中的 `192.168.1.20`。

协作空间的 IP 输入区域也显示查询命令。不要填写网关、子网掩码、`127.0.0.1`、`169.254.*` 或带 `/24` 的内容。局域网使用双方可互通的有线 / Wi-Fi 地址；使用 VPN 时填写双方相应的 VPN 地址。

## 2. 两端打开程序，各自只填对端 IP

| 使用的电脑 | 协作空间输入框填写 |
| --- | --- |
| Windows | Linux 电脑的 IPv4 |
| Linux | Windows 电脑的 IPv4 |

本机 IP 根据访问对端的路由自动选择，不需要手动填写。Linux 客户端启动时自动提供共用信令服务（默认 TCP 8765），Windows 连接填写的 Linux 地址；请保持 Linux 客户端运行。无需用户另行构建、输入两台电脑的地址或启动服务命令。

## 3. 点击“连接服务”

点击「连接服务」会先做一次验证：检查本机活动网卡、对端 ping 和共用服务的 WebSocket 握手，全部过程最多 10 秒。验证通过后自动配对连接（“验证通过”写在输入框下方），无需再点第二次，也不需要输入校验码。服务端按两端连接 IP 和双方填写的对端 IP 匹配；对端未验证或同一 IP 有多个匹配客户端时不会配对。被控端按设置决定是否需要手动允许。IP 地址不是身份认证，关闭二次确认后匹配的对端可直接控制电脑和复制文件。会议仍需双方填写同一会议房间码。屏幕共享和会议使用已验证的本机 IP；两端客户端和信令服务须一起更新。

失败原因直接显示在输入框下方，输入框标红，可修改后重试。成功的对端输入会保留，下次启动仍需重新验证。运行中编辑 IP 会立即取消验证、断开当前会话并禁用远控 / 入会，重新验证后再使用，不需要重启或弹出窗口。服务地址由验证自动设置，界面上不再显示输入框。

对端须开机且网络互通，防火墙允许 ping（ICMP）和 Linux TCP 8765；Linux 缺少 `ping` 时安装 `iputils-ping`。验证通过仍需双方允许 WebRTC 动态端口、具备 GStreamer 插件及摄像头 / 音频设备；基础连通验证不代表真实远控、音视频已经验收。

## 开发与部署

`build.ps1 -Preset windows-release -Deploy` 仅构建、验证和部署，不打开 IP 输入流程。部署目录 `dist/windows-release/bin` 中直接运行 `zjdesk.exe`，保留所有 DLL 和子目录。Linux 需另外构建并更新对应的部署程序；旧 AppImage / Windows 安装包不会因源码修改自动更新。

源码目录的 `直接启动.bat` 直接打开已部署的 Windows 客户端。开发快捷入口 `构建启动.bat` 当前固定使用 `orbbec@10.11.42.4`，通过 SSH 同步、构建并启动双端；它会强制结束两端已有 ZJdesk 进程。该地址仅供当前开发机使用，不会代替界面验证；其他用户直接使用各自的客户端。

开发者可显式传入非回环 `--server ws://IPv4:端口`，两端参数必须指向同一台已填写的电脑；回环参数按 Linux 地址及指定端口处理。Linux 客户端复用同端口已有服务，否则自行监听。默认使用不需要此参数。

`start-both.ps1` 是开发用 SSH 双端构建启动器，未传 `-LinuxSsh` 时要求输入 `用户名@IPv4`。它仍需 SSH 免密、远端开发环境和正确路径（默认 `-LinuxRoot /home/orbbec/ZJdesk/zjdesk`，其他用户应覆盖），不是最终用户运行入口。

对端输入保存在用户设置 `ZJdesk/network.ini` 的 `networkSetup` 分组，不保存放行状态。运行中网络变化的自动重连尚未实现，可重新填写并验证。
