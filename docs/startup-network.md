# 在协作空间验证对端 IP

直接运行程序即可显示主界面，不弹出单独的 IP 输入窗口。协作空间的启动卡片只保留「对端 IP」一个输入框和一个「连接服务」按钮：服务地址由验证自动设置，昵称只在页头填写，验证通过后才会出现「远程控制」按钮。空输入框显示红色边框，远控和会议在验证通过前不可用。构建 / 部署不要求输入 IP，用户实际打开程序时再验证。

## 1. 查询地址

- Windows：双击程序目录下的 `tools\ip-info.cmd`（同目录的 `ip-info.ps1` 由它调用）。
- Linux：在终端执行 `sh tools/ip-info.sh`（当前目录为程序目录；也可用绝对路径）。

脚本只输出两行，直接照抄其一：

```
同局域网：192.168.3.6
不同局域网：100.122.3.99
```

- 「同局域网」取活动物理网卡地址，优先选择有默认网关的网卡，排除代理、Docker 等虚拟网卡。每种地址最多显示一个。
- 「不同局域网」按项目现用的 Tailscale 查询，双方须连接同一 Tailscale 网络。输出「无」表示没有可用的对应地址。
- 同一局域网填对端的「同局域网」地址。跨网时两端都填对端的「不同局域网」地址。

协作空间的 IP 输入区域也提示运行对应脚本。不要填写网关、子网掩码、`127.0.0.1`、`169.254.*` 或带 `/24` 的内容。

## 2. 两端打开程序，各自只填对端 IP

| 使用的电脑 | 协作空间输入框填写 |
| --- | --- |
| Windows | Linux 电脑的 IPv4 |
| Linux | Windows 电脑的 IPv4 |

本机 IP 根据访问对端的路由自动选择，不需要手动填写。Linux 客户端启动时自动提供共用信令服务（默认 TCP 8765），Windows 连接填写的 Linux 地址；请保持 Linux 客户端运行。无需用户另行构建、输入两台电脑的地址或启动服务命令。

## 3. 点击“连接服务”

点击「连接服务」会先做一次验证：检查本机活动网卡、对端 ping 和共用服务的 WebSocket 握手，全部过程最多 10 秒。验证通过后只注册服务并保持在线（“验证通过”写在输入框下方），不会自动配对或开始远控。控制方随后点击「远程控制」才发起配对和控制请求，不需要输入校验码；被控方只需连接服务并按设置确认。结束控制后双方仍在线，可再次点击「远程控制」。服务端按两端连接 IP 和双方填写的对端 IP 匹配；对端未验证或同一 IP 有多个匹配客户端时不会配对。被控端按设置决定是否需要手动允许。IP 地址不是身份认证，关闭二次确认后匹配的对端可直接控制电脑和复制文件。会议仍需双方填写同一会议房间码。屏幕共享和会议使用已验证的本机 IP；两端客户端和信令服务须一起更新。

失败原因直接显示在输入框下方，输入框标红，可修改后重试。成功的对端输入会保留，下次启动仍需重新验证。运行中编辑 IP 会立即取消验证、断开当前会话并禁用远控 / 入会，重新验证后再使用，不需要重启或弹出窗口。每次验证按当前填写的对端 IP 重新选择本机网卡和 Linux 服务地址，支持局域网与 Tailscale 地址互切。开发双端启动器同样使用自动服务地址，显式传入非回环 `--server` 时保留指定地址。服务地址由验证自动设置，界面上不再显示输入框。

对端须开机且网络互通，防火墙允许 ping（ICMP）和 Linux TCP 8765；Linux 缺少 `ping` 时安装 `iputils-ping`。验证通过仍需双方允许 WebRTC 动态端口、具备 GStreamer 插件及摄像头 / 音频设备；基础连通验证不代表真实远控、音视频已经验收。

## 开发与部署

`build.ps1 -Preset windows-release -Deploy` 仅构建、验证和部署，不打开 IP 输入流程。部署目录 `dist/windows-release/bin` 中直接运行 `zjdesk.exe`，保留所有 DLL 和子目录。Linux 需另外构建并更新对应的部署程序；旧 AppImage / Windows 安装包不会因源码修改自动更新。

源码目录的 `直接启动.bat` 直接打开已部署的 Windows 客户端。开发快捷入口 `构建启动.bat` 会通过 SSH 同步、构建并启动双端，自动选取当前可用的媒体地址，并强制结束两端已有 ZJdesk 进程。它依次尝试当前 Linux 开发机的局域网 SSH 地址 `10.11.42.4` 和 Tailscale SSH 地址 `100.87.60.58`，优先使用互通的物理网卡，跨网时回退到两端 Tailscale。启动后仍需各自填写对端所选地址并点击「连接服务」。Linux 的 SSH 地址改变或更换机器时需更新批处理中的 SSH 目标，其他用户直接使用各自的客户端。

开发者可显式传入非回环 `--server ws://IPv4:端口`，两端参数必须指向同一台已填写的电脑；回环参数按 Linux 地址及指定端口处理。Linux 客户端复用同端口已有服务，否则自行监听。默认使用不需要此参数。

`start-both.ps1` 是开发用 SSH 双端构建启动器，未传 `-LinuxSsh` 时要求输入 `用户名@IPv4`。它仍需 SSH 免密、远端开发环境和正确路径（默认 `-LinuxRoot /home/orbbec/ZJdesk/zjdesk`，其他用户应覆盖），不是最终用户运行入口。

对端输入保存在用户设置 `ZJdesk/network.ini` 的 `networkSetup` 分组，不保存放行状态。运行中网络变化的自动重连尚未实现，可重新填写并验证。
