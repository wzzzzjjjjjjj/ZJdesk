# 首次添加设备与自动连接

两端运行新版程序并保持 Tailscale 在线。首次没有保存设备时打开必填的「添加对端设备」窗口，远控和会议在连接验证通过后启用。

## 首次添加

1. 在对端 Tailscale 页面查看 IPv4。也可运行随包脚本，Windows 双击 `tools\ip-info.cmd`，Linux 执行 `sh tools/ip-info.sh`，取输出的「不同局域网」地址。
2. 在任意一端的配置窗口输入对端 Tailscale IPv4，点击「保存并连接」。空输入、普通局域网地址或无效地址会显示错误并保留窗口。
3. 程序先通过 Tailscale 连接并交换设备名称和当前网卡地址，再探测当前同网段的局域网地址。局域网可达时优先使用，否则使用 Tailscale。
4. 另一端尚无设备配置时，收到经过实际 Tailscale 源地址校验的发现信息后自动保存发起端，关闭配置窗口并连接。已有其他对端配置时保留原选择。

首次保存默认开启启动自动连接，内部别名默认 `peer`，可在设置中调整。关闭必填窗口且尚未配置设备会退出程序。已有有效配置会迁移并跳过首次弹窗，但每次启动仍须重新进行连接探测。

## 选择已保存设备

主界面「对端设备」下拉框只显示设备名称，最多保留最近 20 台不同设备。记录以稳定 Tailscale IPv4 去重，每台独立保存名称、局域网缓存和备用 SSH 用户。选择名称立即连接该设备。重新连接时先完成 Tailscale 探测和地址获取，再决定使用局域网或 Tailscale。尚未获取名称时显示「待识别设备」，同名设备使用序号区分。

「添加设备」可以录入其他对端的 Tailscale IPv4。已保存设备再次添加会更新同一条记录。连接状态显示所选设备和当前线路，提示中可查看实际本机与对端地址。主动切换设备会结束旧会话并重新验证。

后台每 5 秒刷新网卡清单，心跳 3 秒超时。局域网候选限定为当前活动以太网 / Wi-Fi 同网段地址，局域网失败时回退 Tailscale，恢复后切回。DHCP 改变后通过稳定 Tailscale IPv4 更新缓存。用户关闭的启动自动连接会被保留，主动断开后收到地址更新不会自行重连。清空设置会删除设备历史并停止自动接受新的发现记录。

## SSH 备用查询

程序在 2.5 秒内未返回地址时尝试备用 SSH，最多每 30 秒一次，每次最多 7 秒。它通过对端 Tailscale IPv4 执行 `ip -4 -o addr show up scope global`，要求 Linux 有 SSH 服务、已信任主机且配置免交互认证。在设置中填写「备用 SSH 用户」，留空沿用现有 SSH 配置。

SSH 返回的网卡清单须包含预期 Tailscale 地址，确认后可探测旧版局域网服务。该备用方式可以补充地址，设备名称由新版程序交换。失败详情显示在连接状态提示中。

## 远控、会议与部署

连接验证通过后仅保持在线，控制方点击「远程控制」才发起配对请求，被控方按设置决定是否手动允许。IP 匹配沿用现有网络信任范围，不能提供身份认证。会议双方仍需填写相同房间码。切换线路时协调层重建会话并保留现有恢复意图，实际双机媒体与输入恢复仍需验收。

两端须允许 TCP 8765，自定义服务端口时使用该端口。Linux 客户端自动提供共用信令服务。自动设备模式从启动参数 `--server` 沿用端口并按当前线路选择服务主机。

Windows 执行 `build.ps1 -Preset windows-release -Deploy` 构建和部署，入口为 `dist/windows-release/bin/zjdesk.exe`，须保留 DLL 和子目录。Linux 需另外构建并更新，旧 AppImage 不会自动更新。源码目录的 `直接启动.bat` 打开已部署程序，开发者的 `构建启动.bat` 通过 SSH 构建并启动双端。

配置保存在用户设置 `ZJdesk/network.ini`。`peer/devices` 保存各设备记录，`peer/*` 保存当前选择与自动连接选项，连接放行状态不持久化。旧的单设备或手动局域网配置保留兼容，可在设置中维护。

Ubuntu 构建、真实双机地址变化与线路切换、实际 SSH 登录及音视频和键鼠恢复以单独的实机验收为准。
