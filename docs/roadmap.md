# 迭代路线

## 0.1 基础框架

目标：可以编译、启动并演示双人房间逻辑，模块有明确职责，失败和资源释放可以回归测试。
包括界面、独立服务、协议、状态机、诊断、授权门禁、可选媒体依赖探测和统一构建测试入口。
验证结果见 validation.md。

## 0.2 媒体依赖与设备预览

- 已实现：GStreamer 1.26.11 启用入口、插件检查与 Windows Runtime 部署。
- 已实现：视频测试源、摄像头本地预览、音频设备枚举和 audiotestsrc。
- 已实现：媒体工作线程、最多两帧交接、独立状态与启停代次。
- 验收分平台记录在 validation.md；Ubuntu 22.04 已增加本机 SDK 构建，物理摄像头仍需单独验收。

## 0.3 摄像头最高模式与双人屏幕共享

- 按用户要求提前实现屏幕共享，语音转写和会议纪要暂缓，人数保持两人。
- 已实现：读取摄像头模式，最高分辨率优先，再取该分辨率最高帧率，预览保留原尺寸。
- 已实现：主屏幕采集、VP8 / WebRTC 单向传输、远端显示、启停及共享方交换。
- 回归：真实 RTP 编解码、旧流事件、同时开始、取消、成员离开及真实桌面颜色变化。
- 双平台与跨机实测记录见 validation.md；长时间运行仍待验收。

### 0.3.1 共享性能与自适应

- 用户要求实际验证 30 / 60 fps，并为不同电脑自动选择分辨率和帧率。
- 已实现真实编码 / 接收 / 交付 / 绘制帧计数，有限档位自动降档与稳定后试探恢复。
- 保留原分辨率优先，先降低帧率，再按比例降低尺寸；摄像头最高模式约定不变。
- 回归覆盖实际变化的桌面、接收端慢显示模拟、在线改变尺寸和帧率；验证结果见 validation.md。
- 不以目标帧率当作实测值，不承诺每台电脑 1080p / 60 fps；本次两台机器的结果见 validation.md。

## 新增：成员语音转写与会议纪要

- 用户新增需求：按发言人记录语音转文字，汇总两人或多人会议并生成会议纪要。
- 用户最新要求暂缓此功能，先完成摄像头最高模式与屏幕共享；房间保持两人。
- 每条发言包含会议标识、成员 ID / 昵称、开始 / 结束时间、文本与转写状态。
- 两端本地音轨分别转写并共享文本，绑定房间身份，避免远端播放声音再次被记成自己的发言。
- 纪要包含讨论要点、已作决策、待办与待确认事项，可查看原始发言和导出。
- 验收：两人交替及同时发言的归属、中文转写、失败提示、退会后旧结果拒绝、纪要可追溯。
- 依赖真实麦克风采集和 0.3 通话链路，不以录入文本或测试源冒充实时会议转写。

## 0.4 Windows 控制 Linux（当前）

- 按用户最新要求，先在 Linux 部署运行，两台电脑各启动一个客户端，先完成 Windows → Linux。
- 已实现：同一 WebRTC 共享连接上的 DataChannel、Linux X11 / XTest、坐标映射和键鼠输入。
- 已实现：Linux 本地确认、拒绝、双方撤销、失焦释放及房间 / 共享退出清理。
- 0.4.2：同房间直接请求，Linux 允许后自动连接桌面；全屏放大 / Esc 恢复，停止自动远控后结束传输。
- 0.4.3：清晰度优先，从主屏幕原尺寸 / 刷新率开始，原尺寸内细化帧率档位，保留低帧率文字码率；跨机实际结果见 validation.md。
- 0.4.4：VP9 4:4:4 保留细字和彩色单像素线，全屏使用完整画面区域；稳定后优先恢复分辨率，实测结果见 validation.md。
- 0.4.5：测量远控输入到画面反馈，并对照 30～200 ms 接收缓冲；在当前两机网络保留通过清晰度与流畅性验收的 200 ms 默认值。
- 验收：真实跨机点击、文字输入、滚轮、拖动，以及拒绝、撤销后不执行和退出释放修饰键。
- 旧共享代次丢弃与 ControlSession 旧授权 / 重放拒绝分别由相关回归验证。
- 后续再实现 Windows 被控、双向远控，以及有语音通话后的摄像头 / 桌面切换。
